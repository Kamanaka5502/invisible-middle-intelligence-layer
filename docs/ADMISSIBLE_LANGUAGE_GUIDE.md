# Admissible Language Guide

This guide protects the Invisible Middle Intelligence Layer from reduction in public, buyer-facing, technical, and practitioner language.

The layer must remain precise, human-preserving, and structurally coherent.

## Core Language

Use:

- structural systems intelligence
- hidden human compensation
- burden transfer
- containment instability
- flourishing restoration
- contextual interpretation
- evidence-supported structural inference
- field-facing intelligence layer
- neurodivergent-rooted detection lens
- public diagnostic/intelligence layer

Avoid:

- productivity tool
- engagement dashboard
- user scoring
- behaviour analytics
- wellbeing app
- UX checker
- AI governance plugin
- workforce monitoring
- compliance wrapper
- kernel
- substrate
- enforcement engine

## Correct Framing

### Instead of:

> The system detects problem users.

Use:

> The layer identifies where system conditions may be creating hidden compensatory burden for people.

### Instead of:

> The dashboard measures employee friction.

Use:

> The dashboard surfaces structural conditions where burden, trust instability, context loss, or participation strain may be forming.

### Instead of:

> AI made the work faster.

Use:

> AI reduced visible production time, but the layer asks whether verification, authority, trust, or correction burden moved into the human field.

### Instead of:

> Neurodivergent users struggle with this system.

Use:

> Neurodivergent and high-sensitivity interaction patterns may reveal unresolved system conditions earlier.

### Instead of:

> The workflow is complete.

Use:

> The workflow completed visibly; the layer asks whether hidden afterwork remains.

## Non-Reduction Tests

Before publishing a phrase, ask:

1. Does it preserve the distinction between visible completion and hidden compensation?
2. Does it avoid making the human the defect?
3. Does it preserve neurodivergent origin as intelligence, not branding?
4. Does it distinguish dashboard surface from intelligence layer?
5. Does it avoid claiming protected substrate or live enforcement runtime?
6. Does it preserve flourishing, not only burden?
7. Does it show where burden moves?

## Technical-Safe Summary

> The repository provides a public-safe runtime scaffold, schemas, reports, and tests for structural interpretation of hidden human compensation. It does not expose protected Elyria / Veritas substrate logic, scoring law, kernelization, or live enforcement runtime.

## Final Standard

Language is admissible only if it makes the hidden burden field clearer without flattening the human field that revealed it.
